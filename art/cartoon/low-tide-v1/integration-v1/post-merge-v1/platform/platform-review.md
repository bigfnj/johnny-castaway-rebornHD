## Execution and limits

The first main gate attempt, `low-tide-main-v1`, completed the clean build, all smoke groups, and native wave/palm regression, but its launcher stopped during approval-history regression at `gate-child-became-foreground`. Its immediately preceding input-desktop observation passed. The launcher did not record the failing foreground PID or process creation time, so neither PID reuse nor actual foreground takeover is established. The attempt is not a full-gate PASS. Its log and launch/source witnesses are retained under `attempt-v1/`.

The single retry, `low-tide-main-v2`, passed the full configure/build, smoke and regression gate in 162.755 seconds with exit 0. It used the exact frozen launcher and every existing guard, with a thin exception-only observer. The input desktop remained unchanged across 310 checks; 244 owned windows were observed on the private desktop. All 32 retained PPMs have complete 1280x960 payloads and their capture markers. The build reported no warnings, protected sources remained unchanged, and source/deployed archives both equal `a89874307d77d805ab41ef55ba87e45e98ce6e9e589e1bea0d081629e5745d66`. `verification.json` and `attempt-v2/` preserve the result. This success does not explain the first attempt's failure. The parent separately retained four passing main CI jobs in `../main-ci.json`.

`native-binding.json` compares the current production/deployed archive and all retained feature runtime/helper hashes with the accepted Linux/Xvfb scene evidence. This is a new identity readback, not new Linux rendering. The historical proof covers 16 smoke and 16 fresh-repeat captures, with 81 whole-scene-identical high-tide control displays. The frozen capture helper intentionally pins the pre-promotion production archive and must not be rerun against current main as though that were its input.

No new physical audio, Linux window-manager fullscreen, macOS device rendering, Web-browser fullscreen, original-executable, sanitizer, race-detector or performance test is claimed. The Windows gate uses a private inactive desktop; its automatic scene/ownership tests are distinct from physical-display inspection.
